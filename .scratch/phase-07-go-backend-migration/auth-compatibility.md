# Better Auth compatibility findings

These findings were collected for Phase 7 Ticket 01 using the lockfile-pinned
Better Auth 1.7.3 and `@better-auth/utils` 0.4.2 implementation. The values in
`fixtures/better-auth-scrypt-v1.json` are synthetic and are not user
credentials.

## Password hashes

`node_modules/@better-auth/utils/dist/password.node.mjs` and
`password.node.cjs` implement password hashing as:

- scrypt with `N=16384`, `r=16`, `p=1`, `dkLen=64`;
- NFKC normalization of the submitted password before derivation;
- a randomly generated 16-byte salt rendered as lowercase hex, then passed to
  scrypt as the UTF-8 bytes of that hex text;
- stored format `saltHex:derivedKeyHex`.

An isolated Go probe using `golang.org/x/crypto/scrypt` v0.58.0 and
`golang.org/x/text/unicode/norm` v0.43.0 verified the Better Auth fixture for
both decomposed and composed forms of the same NFKC password and rejected a
wrong password. The same behavior is now covered by a repository auth
integration test for Better Auth. The Go implementation must retain
constant-time derived-key comparison and bounded hash parsing.

## Session cookie and lifecycle

`node_modules/better-call/dist/crypto.cjs` signs the database session token
using HMAC-SHA256 with the configured auth secret. It base64-encodes the
signature and URL-encodes `<database-session-token>.<signature>` as the cookie
value. Go can verify that format with standard-library HMAC, provided the
secret and token bytes are preserved exactly.

For the current local HTTP test origin, the cookie is
`better-auth.session_token`; HTTPS production uses the `__Secure-` prefix.
Default attributes are `Path=/`, `HttpOnly`, `SameSite=Lax`; session max age is
604800 seconds. The database `session.expires_at` controls validity/revocation.
Better Auth defaults to a 7-day expiry and a 1-day rolling update age. Reads
that cross the refresh threshold update the database expiry and emit a renewed
cookie. Sign-out deletes the database session and expires the browser cookie.

The auth integration tests now prove the generated cookie signature matches
the persisted token and test renewal, invalidation, and expected cookie
attributes. The synthetic `better-auth-session-cookie-v1.json` fixture is
generated by the pinned Better Auth `better-call` signer; Go verifies it and
uses it to retrieve a matching test-database session row. SSR must still
preserve every `Set-Cookie` response value in the Next-to-Go transport; Ticket
09 covers that boundary.

## Origin, input, and safe errors

Current server auth derives the trusted origin from `BETTER_AUTH_URL`, allows
only that origin, and explicitly enables both origin and CSRF checks. Sign-up
password length is 8–128 and the username callback rejects blank names. Invalid
sign-in credentials map to one safe `INVALID_EMAIL_OR_PASSWORD` category.
These behaviors are captured by the current integration suite and the
initial `api/openapi.yaml` auth contract.

Better Auth enables its in-memory rate limiter in production by default: 100
requests per 10 seconds per path, with a 3-request/10-second special rule for
sign-in and sign-up. The Go API uses the same production activation through
`BACKEND_ENV=production` (or `NODE_ENV=production`) and the same limits. Its forwarded-IP parsing accepts a
single valid `X-Forwarded-For` address; an absent or multi-hop untrusted value
falls back to a shared per-path bucket, matching Better Auth's default.

## Evidence

- `src/lib/auth/server.ts`, `src/lib/auth/origin.ts`, and
  `src/lib/auth/options.ts` define the current server configuration.
- `src/db/schema/auth.ts` defines the existing user/session/account schema.
- `src/lib/auth/auth.integration.test.ts` proves the current DB-backed auth
  behavior on the isolated test database.
- `api/openapi.yaml` and generated `src/lib/api/generated.ts` define the first
  Go-facing auth transport contract.
- Current fixture cross-verification was run with Go 1.27.1. The scrypt
  implementation and Unicode normalization APIs are documented by the
  official [Go x/crypto module](https://pkg.go.dev/golang.org/x/crypto) and
  [scrypt package](https://github.com/golang/crypto/blob/master/scrypt/scrypt.go).
